# Public decision register

Technical decisions that are safe to publish. This is the register for the public repository; the project owner keeps other records privately (rights and authorisation records, internal review records and operational notes). Decision labels such as `D-0xx` that appear in code comments or in generated records refer to that private internal register and are not published.

**Implementation status:** no LLM provider adapter exists yet. The provider choices below are configuration and design decisions (typed settings, `.env.example`, documentation), not completed integrations, and they are not evidence of production readiness.

| ID | Decision | Detail |
|---|---|---|
| PD-01 | The existing 26-table database schema is preserved | PostgreSQL schema `concepttrail` with `VARCHAR` identifiers such as `subject_id`. `embedding_chunk` keeps its nine agreed columns. Alembic revision `0001` reproduces the schema on an empty database; an existing database is stamped, never upgraded through it. See `docs/DATABASE_SCHEMA.md`. |
| PD-02 | Student authentication uses a platform-issued username and an individual 8-digit PIN | The platform issues the username. PINs are stored only as secure hashes, login is rate-limited, and identity is derived server-side. This is a design decision; no authentication code exists yet. |
| PD-03 | Teacher authentication uses school email and password, with controlled onboarding | Teachers are onboarded through a controlled process rather than open self-registration. Passwords are stored only as secure hashes. This is a design decision; no authentication code exists yet. |
| PD-04 | The local development LLM is Qwen 3.5 9B through Ollama | Provider `ollama`, model `qwen3.5:9b`, `http://localhost:11434/api/chat`, initial context 4096 tokens, thinking disabled, JSON Schema structured output. `localhost` is reachable only on the developer's machine, so a remote deployment needs separate inference infrastructure; never expose the Ollama port publicly. |
| PD-05 | Groq GPT-OSS 120B is a cloud fallback candidate; fallback stays disabled | Provider `groq`, model `openai/gpt-oss-120b`, `https://api.groq.com/openai/v1`. `LLM_FALLBACK_ENABLED=false`. It may be enabled only after provider integration, security, privacy and reliability tests and explicit owner approval. Fallback is allowed only for transient failures, never around validation, safety, rights or insufficient-evidence outcomes. |
| PD-06 | Gemini and DeepSeek are not current providers | Both were considered earlier and are not selected. No integration for either exists. |
| PD-07 | The embedding model and vector dimension are undecided | They will be chosen after a retrieval evaluation on English and Hindi content across the five subjects. The database `VECTOR` column stays unbounded and no dimension-specific index is created until then. |
| PD-08 | Deterministic algorithms own scoring, mastery, prerequisites, access control and adaptive policy; AI generates language from approved retrieved evidence | Bayesian knowledge tracing, graph logic and policy rules are deterministic and tested. A language model never sets scores, mastery, graph edges, roles, access rights or next-step decisions. Answers must be grounded in retrieved evidence with citations resolved from database records, and must abstain when evidence is insufficient. No model is trained or fine-tuned in the first release. |
| PD-09 | External processing of student or textbook content requires separate authorisation and review | Rights are purpose-specific: internal processing, external-model processing, indexing, display, redistribution and training are separate decisions. Selecting a provider does not authorise sending content to it. Student names, contact details, identifiers and unnecessary learner history are never sent to model providers. |
| PD-10 | The React frontend lives in `frontend/` and talks to the backend only through the HTTP API | Owner instruction (2026-11-01) superseded the earlier "frontend maintained separately" scope. The Vite + React + TypeScript app in `frontend/` uses the OpenAPI contract, bearer tokens kept in session storage, and never connects to PostgreSQL, Redis or Ollama. A contract test fails if it calls a path missing from `docs/openapi/openapi-v1.json`. See `docs/FRONTEND_INTEGRATION.md`. |
| PD-11 | Database migrations require explicit approval | Any schema change needs a reviewed migration and the owner's approval. Existing data is never dropped, truncated or recreated. See `app/db/migrations/README.md`. |
| PD-12 | Bell-Ringer topics are chosen by deterministic rules; cycles are per topic and need an approved migration | A topic is flagged when enough enrolled learners have an estimate, at least a minimum number of *different* learners are below the weak cut-off, and they form a minimum share (`BELL_RINGER_*` settings, provisional). The root gap is traced backwards through the prerequisite graph; the warm-up card is built from stored questions by a fixed template, never by a language model. Cycle persistence uses the proposed additive migration `db/proposals/0004_bell_ringer_cycle.py` and is disabled until the owner approves it. |
